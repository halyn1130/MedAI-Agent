# Risk Agent 추가 수집 데이터

## 목적과 범위

기업·제품 조사 Agent가 기업 프로필과 기초 근거를 전달한 이후, 운영·사업 지속성을 판단하는 데 부족한 정보만 추가 수집한다. 수집 범위는 **외부 자원 의존, 핵심 역할 연속성, 운영 사건과 대응**이다.

기업 조사 단계에서 확보한 협력 관계, 경영진 정보, 공식 공지·사건 원문을 재사용한다. Risk Agent는 현재 상태, 후속 대응, 대체 수단을 중심으로 보완한다. 임상·인허가 적합성, 시장성, 매출·성장률은 다른 분석 Agent의 담당이며 여기서 다시 평가하지 않는다.

이 문서는 수집 데이터 설계안이다. 아래 CSV와 공통 필드가 현재 코드에 모두 구현되어 있다는 뜻은 아니다. 현재 실행 입력은 기업 프로필과 근거를 포함한 State JSON이며 실제 형식은 `schema.py`와 `README.md`를 따른다.

## 1. 외부 자원 의존

**확인할 질문:** 핵심 외부 협력이 중단돼도 제품·서비스를 계속 제공할 수 있는가?

| 수집 항목 | 기업 조사에서 받는 정보 | Risk에서 추가 확인할 정보 |
|---|---|---|
| 협력 기관·목적 | 병원·대학·데이터 제공기관·유통사·기술 공급사와 협력 목적 | 핵심 사업 운영에 필요한 자원인지, 관련 제품은 무엇인지 |
| 협력 시점·상태 | 체결 발표일과 발표 내용 | 공개된 계약 기간, 갱신·종료·변경, 현재 상태 |
| 의존 관계 | 공개된 협력 설명 | 독점·단독 공급·사용 제한이 명시됐는지 |
| 대체 수단 | 공개된 다른 협력 기관 | 같은 자원을 대체할 수 있다는 근거, 자체 확보·전환 계획 |
| 중단 시 영향 | 공개된 종료·중단 공지 | 실제 운영 영향과 회사의 대응·복구 설명 |

우선 출처는 기업·상대 기관의 공식 발표, 공개 계약·공시, 후속 공지다. 뉴스는 원출처와 발표 시점을 확인한다.

공개 파트너가 한 곳이라는 이유로 단독 의존을 확정하지 않는다. 파트너 수만으로 대체 가능성을 판단하지 않는다. 계약 금액과 매출 기여도 평가는 실적 Agent에 맡긴다.

## 2. 핵심 인력·역할 연속성

**확인할 질문:** 핵심 업무의 담당 역할이 유지되며, 인사 변동 시 업무를 이어갈 체계가 확인되는가?

| 수집 항목 | 기업 조사에서 받는 정보 | Risk에서 추가 확인할 정보 |
|---|---|---|
| 인물·직책·역할 | 창업자·대표·주요 임원과 공개된 담당 업무 | 기준일에 해당 역할을 맡고 있다는 근거 |
| 인사 변동 | 공식 선임·퇴임·교체 발표 | 적용 시점, 현재 직책, 후속 발표 |
| 후임·업무 인계 | 공개된 후임 정보 | 후임 선임·직무대행·업무 인계 여부 |
| 역할 유지 체계 | 공개 조직·역할 설명 | 공동 책임·역할 분담·연속성 대응에 관한 근거 |

우선 출처는 공식 경영진 소개, 선임·퇴임 공지, 공개 공시다. 오래된 인터뷰만으로 현재 재직 상태를 확정하지 않는다.

홈페이지에서 이름이 사라졌다는 이유만으로 퇴임을 확정하지 않는다. 후임 미공개를 실제 공석으로 처리하지 않는다. 개인의 사생활이나 업무와 무관한 정보는 수집하지 않는다.

## 3. 운영 사건과 대응

**확인할 질문:** 운영에 영향을 준 사건이 있으며, 기준일 현재 영향이 남아 있는가?

| 수집 항목 | 기업 조사에서 받는 정보 | Risk에서 추가 확인할 정보 |
|---|---|---|
| 사건 유형·내용 | 서비스 중단·종료, 제휴 종료, 공개된 사고·분쟁 원문 | 원문으로 확인되는 사실과 당사자 주장의 구분 |
| 대상·범위 | 관련 제품·서비스·기관 | 기업 전체인지 특정 제품·지역에 한정되는지 |
| 날짜 | 발생일·발표일 | 변경·복구·종료 시점과 기준일 당시 상태 |
| 운영 영향 | 공지된 중단·제한 내용 | 실제 공급·서비스 영향과 지속 기간 |
| 대응 | 회사의 최초 설명 | 복구·시정·대체 공급 등 후속 조치 |
| 해결 상태 | 후속 설명 | 재개·해결의 근거, 미해결 사항 |

우선 출처는 기업·상대 기관의 공지, 관련 공식 기록, 원출처 보도다. 사건 보도뿐 아니라 후속 해결 자료도 함께 조사한다.

과거 사건을 현재의 미해결 위험으로 그대로 취급하지 않는다. 공개된 분쟁 주장을 확정된 위법 사실로 바꾸지 않는다. 규제 사건의 허가·법적 상태는 임상·인허가 Agent 결과를 참조하고 Risk는 확인된 운영 영향과 대응에 집중한다.

## 공통 기록 필드

| 필드 | 의미와 기록 규칙 |
|---|---|
| `record_id` | 수집 항목 고유 ID. 동일 항목 보완 시 유지 |
| `company_id` | 기업 식별자 |
| `product_id` | 관련 제품 식별자. 기업 전체 또는 미확인일 때는 별도 범위 설명과 함께 `null` |
| `category` | `external_dependency`, `key_person_continuity`, `operational_incidents` |
| `statement` | 출처에서 확인한 사실 또는 출처의 주장임을 명시한 문장 |
| `source_ids` | 출처 목록의 ID 참조. 복수 근거 연결 가능 |
| `event_date` | 실제 발생·변경일. 모르면 `null` |
| `as_of` | 공통 분석 기준일 |
| `verification_status` | 확인·부분 확인·미확인. 구체적 열거값은 통합 스키마에서 확정 |
| `current_status` | 협력·재직·사건 등 해당 항목의 상태와 그 근거 |
| `missing_items` | 아직 확인하지 못한 내용 |

출처는 별도 목록에 다음 정보를 기록한다.

| 필드 | 의미 |
|---|---|
| `source_id` | 출처 고유 ID |
| `title`, `publisher`, `source_type` | 제목·발행기관·자료 종류 |
| `url` | 원문 URL |
| `published_at` | 발행일. 모르면 `null` |
| `checked_at` | 실제 조회일 |
| `excerpt`, `locator` | 판단에 사용한 원문 발췌와 페이지·절 등 위치 |

URL만 저장하지 않고 원문 발췌를 함께 보존한다. 조회일과 발행일을 구분하고, 기준일 이후 공개 자료는 기준일 당시 판단 근거에서 제외한다. 발행일 미상 자료는 기준일 당시 존재를 확인할 수 있는지 별도로 기록한다.

## 수집용 파일 구성안

```text
data/risk/
├── partnerships.csv        # 외부 자원·협력 상태·대체 수단
├── leadership.csv          # 핵심 인력·역할·변동·후임
├── operational_events.csv  # 사건·영향·대응·해결 상태
└── sources.csv             # 출처·날짜·원문 발췌
```

위 파일은 아직 생성하지 않은 수집용 제안이다. 실제 저장 시 복수 `source_ids` 등 목록 필드의 직렬화 규칙을 정해야 한다. 현재 Risk Agent는 이 CSV들을 직접 읽지 않으므로 사용하려면 State JSON으로 변환하는 단계가 필요하다.

## 추가 조사 흐름과 종료

1. 기업 조사 결과를 세 범주에 매핑하고 기존 출처를 재사용한다.
2. 현재 상태·후속 대응·대체 수단의 결측과 자료 충돌을 확인한다.
3. 결측 항목별 질문을 만들고 공식 자료를 우선 검색한다.
4. 기업·제품·날짜·원문을 대조하고 중복 보도를 구분한다.
5. 확인 사실, 잠재 영향, 대응, 미확인 사항, 실사 질문을 나누어 반환한다.
6. 검색 예산이 소진되거나 추가 공개 근거를 확보하지 못하면 한계를 기록하고 종료한다.

정상 검색 후 미발견, 검색 실패, 비공개, 실제 부정 사실은 구분한다. 자료 미발견은 안전 또는 고위험의 증거가 아니다. 공개 자료로 확인할 수 없는 계약 조항·승계 계획 등은 회사에 물어볼 실사 질문으로 남긴다.

투자 심사에서 재조사를 요청하면 기존 판단과 근거, 대상 항목 ID, 질문, 완료 조건, 검색 기간·예산을 받아 해당 항목만 보완한다. 새 자료가 없더라도 기존 해석이 과도했다면 수정할 수 있다.

## 투자 심사에 전달할 내용

- 범주별 확인 사실과 출처
- 운영 지속성에 미칠 수 있는 영향과 해석의 한계
- 공개된 대응·대체 수단 및 사건의 현재 상태
- 조사 범위, 검색 실패, 남은 미확인 사항
- 추가 실사 질문과 보완 시 변경된 내용

수집 데이터 자체에서 투자 적격 여부를 단정하지 않는다. 현재 Risk 구현은 사실·영향 분석을 제공하며, 통합 설계의 운영 대비 체크와 C6 채점 연결은 별도 구현 대상이다.
